# 16. Agent Integration Surfaces: Driving Coding Agents Programmatically

> Part of the Multiverso research corpus - https://github.com/coagente/multiverso - Cutoff: 2026-08-12

## Why this matters for Multiverso

Multiverso's core loop — one Intent, N isolated candidate Worlds, evidence-gated admission — needs a **generator-agnostic way to spawn a coding agent inside a world, cap its spend, watch what it does, and harvest three artifacts: the diff, the cost, and the transcript**. Chapter 10 established that the defensible wedge is the vendor-neutral admission layer; that neutrality is only real if the control plane can drive Claude Code, Codex, OpenHands, and future agents through one `AgentAdapter` interface. This chapter maps the exact flags and APIs of every major agent surface as of 2026-08-12 and specifies that interface. The headline finding: **the surfaces have converged on non-interactive JSON-event modes, but only Claude Code enforces a native dollar budget cap; every other tool needs control-plane-side budget enforcement**, and no tool exposes seeds or determinism — reproducibility must come from receipts, not replay.

## State of the art

### (a) Claude Code headless and the Claude Agent SDK

Claude Code is the most complete programmatic surface. `claude -p "<prompt>"` runs non-interactively; `--output-format` accepts `text`, `json`, or `stream-json` (newline-delimited events), and `--input-format stream-json` allows message injection mid-run ([CLI reference](https://code.claude.com/docs/en/cli-reference)). With `--output-format json`, the result payload includes `total_cost_usd`, a per-model cost breakdown, `session_id`, and usage — explicitly documented as client-side estimates ([headless docs](https://code.claude.com/docs/en/headless)). The stream's last line is a `result` message with final text, cost, and session metadata; a `system/init` first event reports model, tools, `mcp_servers` (with per-server `status` and an `mcp_server_errors` array for CI gating), and a `capabilities` array for feature detection; `system/api_retry` events surface rate-limit/overload retries with `error` categories such as `rate_limit`, `overloaded`, `billing_error` ([headless docs](https://code.claude.com/docs/en/headless)).

Budget and control knobs, all print-mode: `--max-turns N` (exits with an error at the limit), and — unique among all surveyed tools — **`--max-budget-usd`, a native dollar cap that includes subagent spend and stops still-running background subagents when reached** (requires v2.1.217+) ([CLI reference](https://code.claude.com/docs/en/cli-reference)). `--permission-mode` accepts `default`, `acceptEdits`, `plan`, `auto`, `dontAsk`, `bypassPermissions`; `--allowedTools`/`--disallowedTools` take permission-rule patterns like `Bash(git diff *)`; `--dangerously-skip-permissions` equals `bypassPermissions`. `--json-schema` returns validated structured output in a `structured_output` field (invalid schemas fail fast since v2.1.205). `--worktree/-w <branch>` creates and works in a git worktree; `--mcp-config` loads MCP servers (with `-p`, Claude Code waits up to `MCP_TIMEOUT` for servers to connect before turn one, v2.1.221+), and `--strict-mcp-config` ignores all other MCP configuration. `--bare` skips auto-discovery of hooks, skills, plugins, MCP servers, and CLAUDE.md — "the recommended mode for scripted and SDK calls," slated to become the `-p` default — which is exactly what a control plane wants for hermetic candidate runs ([headless docs](https://code.claude.com/docs/en/headless)).

Hooks turn Claude Code into a structured event emitter. Events include `PreToolUse`, `PostToolUse`, `Stop`, `SessionStart`, `SessionEnd`, `SubagentStart`/`SubagentStop`, `UserPromptSubmit`, `PreCompact`, plus newer ones (`PermissionRequest`, `PostToolBatch`, `WorktreeCreate`). Hooks receive JSON on stdin (`session_id`, `transcript_path`, `cwd`, `tool_name`, `tool_input`, `tool_use_id`, `permission_mode`); exit code 2 blocks the action, exit 0 with JSON can return `hookSpecificOutput.permissionDecision: "allow"|"deny"`, `updatedInput`, or `continue: false` with `stopReason` ([hooks reference](https://code.claude.com/docs/en/hooks)). Critically for Multiverso, `--include-hook-events` folds hook lifecycle events into the stream-json output, and `--forward-subagent-text` emits subagent messages with `parent_tool_use_id` so the full nested transcript tree can be reconstructed for lineage ([headless docs](https://code.claude.com/docs/en/headless)). The `transcript_path` field points at the persisted JSONL transcript — the raw material for a content-addressed evidence store.

The [Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview) (Python `claude-agent-sdk`, TypeScript `@anthropic-ai/claude-agent-sdk`) is "Claude Code as a library" — same loop, in-process. `ClaudeAgentOptions` exposes `allowed_tools`, `permission_mode`, `max_turns`, **`max_budget_usd`**, `cwd`, `mcp_servers`, `hooks` (as async callbacks via `HookMatcher`), `system_prompt`, `model`, `setting_sources`, `include_partial_messages`, `fork_session`, and a `can_use_tool` permission callback returning `PermissionResultAllow`/`PermissionResultDeny`; the terminal `ResultMessage` carries `total_cost_usd`, `usage`, `num_turns` ([Python SDK reference](https://code.claude.com/docs/en/agent-sdk/python)). For non-Python/TS hosts, Anthropic's own guidance is to run the CLI as a subprocess with `-p --output-format json` ([SDK overview](https://code.claude.com/docs/en/agent-sdk/overview)).

### (b) OpenAI Codex CLI, SDK, and cloud

`codex exec` (alias `codex e`) is Codex's non-interactive mode. `--json` turns stdout into a JSONL stream with events `thread.started`, `turn.started`, `turn.completed` (includes token usage), `turn.failed`, `item.started`/`item.completed`; item types cover agent messages, reasoning, command executions, file changes, MCP tool calls, web searches, and plan updates ([non-interactive mode docs](https://developers.openai.com/codex/noninteractive)). `--output-last-message/-o <path>` writes the final message to a file; `--output-schema <file>` requests a final response conforming to a JSON Schema. Sandbox and approvals: `-s/--sandbox` takes `read-only | workspace-write | danger-full-access` (exec defaults to read-only); `-a/--ask-for-approval` takes `untrusted | on-request | never`; `--full-auto` is deprecated in favor of `--sandbox workspace-write`; `--dangerously-bypass-approvals-and-sandbox` (`--yolo`) is documented as "only use inside an isolated runner" ([CLI reference](https://developers.openai.com/codex/cli/reference)). Other adapter-relevant flags: `-C/--cd` sets the workspace root, `-m/--model` overrides the model, `-p/--profile` selects a `config.toml` profile, `-c key=value` overrides any config key, `--ephemeral` skips persisting session files, `--skip-git-repo-check` bypasses the requirement to run inside a git repository, and `codex exec resume <SESSION_ID>` / `resume --last` continues a session ([CLI reference](https://developers.openai.com/codex/cli/reference)). `config.toml` carries `model`, `model_reasoning_effort`, `approval_policy`, `sandbox_mode`, `profiles`, and `mcp_servers` tables ([config sample](https://developers.openai.com/codex/config-sample)). For CI, the docs recommend setting `CODEX_API_KEY` for the single `codex exec` invocation. **There is no native turn or dollar cap in `codex exec`** — budget enforcement is the caller's job — and exit codes are not systematically documented.

The [Codex SDK](https://learn.chatgpt.com/docs/codex-sdk) (`@openai/codex-sdk` for Node 18+, `openai-codex` for Python 3.10+, which talks JSON-RPC to the local Codex app-server) exposes `startThread()` / `resumeThread(threadId)` / `run(prompt)`, with per-turn sandbox presets (`Sandbox.read_only`, `Sandbox.workspace_write`, `Sandbox.full_access`). Codex **cloud** tasks are drivable from the CLI (`codex cloud exec --env ENV_ID "<task>"`, with `--attempts` to request multiple parallel cloud attempts, plus task `list`/`status`/`diff`/`apply`) but there is no public REST API for cloud environments; environment lifecycle scripting is an open feature request ([openai/codex#24777](https://github.com/openai/codex/issues/24777); cloud CLI details per secondary sources [1](https://codex.danielvaughan.com/2026/04/08/codex-cloud-task-application/), [2](https://toolsbase.dev/en/reference/codex-commands) — treat exact cloud flags as unverified).

### (c) OpenHands, Aider, opencode, Jules, GitButler

**OpenHands** ships a first-class embedding path: the [agent SDK](https://github.com/OpenHands/software-agent-sdk) splits into `openhands-sdk`, `openhands-tools`, `openhands-workspace`, and `openhands-agent-server`. The minimal loop is `LLM(model=..., api_key=...)` → `Agent(llm=llm, tools=[...])` → `Conversation(agent=agent, workspace=cwd)` → `conversation.send_message(...)` → `conversation.run()`, with local or ephemeral Docker/Kubernetes workspaces via the REST-based Agent Server ([SDK docs](https://docs.openhands.dev/sdk)). Cost observability is the best in class: `llm.metrics` (an instance of `Metrics`) exposes `accumulated_cost`, `accumulated_token_usage` (prompt/completion/cache read/cache write/reasoning tokens), per-call `costs` and `response_latencies`, and `conversation.conversation_stats.get_combined_metrics()` aggregates across all LLMs in a conversation ([metrics guide](https://docs.openhands.dev/sdk/guides/metrics.md)) — though no native spend *limit* is documented. The CLI has a headless mode: `openhands --headless -t "task"` (or `-f task.txt`) with `--json` for JSONL event output; headless "always runs in 'always-approve' mode" ([headless docs](https://docs.openhands.dev/openhands/usage/cli/headless.md)) — isolation is therefore mandatory.

**Aider** remains the minimal scriptable baseline: `aider --message "<instruction>" --yes` processes one instruction and exits; `--no-auto-commits` disables its default auto-commit behavior (relevant because Multiverso wants to own the commit boundary), `--dry-run` previews. The Python API (`Coder.create(main_model, fnames, io=InputOutput(yes=True))`, `coder.run(...)`) is explicitly "not officially supported or documented, and could change... without backwards compatibility" ([Aider scripting docs](https://aider.chat/docs/scripting.html)). No event stream, no budget cap, no structured output.

**opencode** offers `opencode run` with `--model provider/model`, `--agent`, `--session`/`--continue`, `--format` (`default` or `json` raw events), and `--attach` to target a running server; `opencode serve` runs a headless HTTP server, and the typed [`@opencode-ai/sdk`](https://opencode.ai/docs/sdk/) (generated from the server's OpenAPI spec) exposes `session.create()`, `session.prompt()`, and `event.subscribe()` as an SSE stream ([CLI docs](https://opencode.ai/docs/cli/)). Cost reporting exists only as aggregate `opencode stats`; no per-run budget cap.

**Google Jules** shipped a public API, but it is explicitly alpha: base endpoint `https://jules.googleapis.com/v1alpha/`, auth via `X-Goog-Api-Key` (max 3 keys/user), `POST /sessions` with `prompt`, `sourceContext.githubRepoContext`, optional `automationMode: "AUTO_CREATE_PR"` and `requirePlanApproval`; progress is observed by polling `GET /sessions/{id}/activities` and follow-ups go through `:sendMessage` ([Jules API](https://developers.google.com/jules/api)). Google states "we may change specifications, API keys, and definitions as we work toward stabilization." Jules is cloud-execution-only against GitHub repos — there is no local worktree to diff; the candidate artifact is a remote branch/PR.

**GitButler's `but` CLI** is not a generator but a VCS surface *for* agents: `but agent setup` installs a GitButler skill for "Codex, Claude Code, Cursor, GitHub Copilot, Windsurf / Devin, OpenCode" that teaches the agent to use `but` commands (`but commit` with hunk IDs, `but amend`, `but squash`, `but pr`, `but land`, `but oplog` for state restore) instead of raw git, sorting multiple concurrent agents' changes into virtual branches within **one shared working directory** ([GitButler ai-agents docs](https://github.com/gitbutlerapp/gitbutler-docs/blob/main/content/docs/ai-agents/overview.mdx)). The earlier integration wired `but claude pre-tool` / `post-tool` / `stop` directly into Claude Code's `PreToolUse`/`PostToolUse`/`Stop` hooks to attribute file changes to per-session branches ([GitButler blog](https://blog.gitbutler.com/parallel-claude-code); the hook commands still exist — [gitbutler#13316](https://github.com/gitbutlerapp/gitbutler/issues/13316)). GitButler's own docs position shared-workdir virtual branches for *independent* tasks and recommend worktrees for "competing attempts at the same task" ([parallel agents doc](https://github.com/gitbutlerapp/gitbutler-docs/blob/main/content/docs/ai-agents/parallel-agents.mdx)) — which is Multiverso's N-candidate regime, confirming worktree/VM isolation as the right substrate for Worlds.

### (d) Cross-cutting adapter mechanics

**Budget caps.** Native support: Claude Code `--max-turns` + `--max-budget-usd` (CLI) and `max_turns` + `max_budget_usd` (SDK). OpenHands: measure-only (`accumulated_cost`), no cap. Codex, Aider, opencode, Jules: none. Therefore the control plane must own a three-way budget: (1) wall-clock timeout with SIGTERM (Claude Code aborts the turn, terminates the Bash process tree, runs `SessionEnd` hooks, and exits 143 ([headless docs](https://code.claude.com/docs/en/headless))); (2) a token/cost meter fed by the event stream (`turn.completed` token usage in Codex; `result.total_cost_usd` in Claude Code; `Metrics` in OpenHands); (3) the tool's native cap as an inner guard where available. Chapter 3's evidence-aware scheduler consumes exactly this meter.

**Diff capture.** The robust pattern is control-plane-owned: `git worktree add <wt> <base-commit>` per candidate, run the agent with `cwd`/`-C` pinned to the worktree, then `git -C <wt> add -A && git -C <wt> diff --binary <base-commit>` (staging first captures untracked files). Record the base commit OID with the patch — the pair is the candidate's identity for evidence binding (ch. 7). Agents that commit on their own (Aider by default; Claude Code when prompted; `but`-instructed agents) are handled by diffing `<base>..HEAD` instead; disable auto-commit (`--no-auto-commits`) when the control plane wants a single clean patch. Jules is the exception: the artifact is a remote branch fetched from GitHub.

**Exit codes and failure taxonomy.** Claude Code: 0 success, non-zero failure, 1 on `--max-turns` exhaustion, 143 on SIGTERM; in-run failures (e.g., missing auth) are printed *as the result* on stdout, so exit code alone is insufficient — parse the result message's error state ([headless docs](https://code.claude.com/docs/en/headless)). Codex documents non-zero on failure but no systematic table; `turn.failed` events are the reliable signal. The adapter should normalize into: `COMPLETED`, `BUDGET_EXCEEDED{turns|usd|wallclock}`, `INTERRUPTED`, `CONFIG_ERROR` (bad flag/schema/MCP — Claude Code's `mcp_server_errors` and `--json-schema` validation fail fast), `PROVIDER_ERROR` (rate limit/overload — `system/api_retry`), `CRASH`.

**Transcript capture for lineage.** Claude Code persists a JSONL transcript (`transcript_path` in hook input) and the full stream-json output is itself a replayable transcript, including subagent trees via `parent_tool_use_id`. Codex persists session files by default (disable with `--ephemeral`) and identifies them by `SESSION_ID` for `codex exec resume`. OpenHands exposes the event stream in-process. The adapter should tee the raw event stream to CAS and record its digest in the world's receipt; `session_id`/thread ID enables the REPAIR decision to resume a candidate (`--resume <id> --fork-session` in Claude Code forks a new session ID for branching repair attempts ([CLI reference](https://code.claude.com/docs/en/cli-reference))).

**Model pinning, seeds, determinism.** Every surface pins models (`claude --model claude-sonnet-5` plus `--effort low..max`; Codex `-m` plus `-c model_reasoning_effort=high`; OpenHands `LLM(model=...)`; Aider `Model(...)`; opencode `--model provider/model`). **No surveyed CLI exposes a sampling seed**, and on Anthropic's current models the point is moot: `temperature`/`top_p`/`top_k` were removed on Opus 4.7+ (requests 400), and Anthropic notes temperature-0 never guaranteed identical outputs anyway ([model migration guide](https://platform.claude.com/docs/en/about-claude/models/migration-guide)). Consequence for the PRD: candidate diversity is free, replay-determinism is unattainable — reproducibility must be *evidential* (pinned model ID, CLI version from `claude --version`/`codex --version`, transcript digest in the receipt), matching ch. 7's integrity-not-veracity framing.

**Rate limits for N parallel runs.** All candidates in a race typically share one org's ITPM/OTPM budget ([Anthropic rate limits](https://platform.claude.com/docs/en/api/rate-limits)); N parallel worlds multiply burn against the same pool. The adapter surfaces backpressure natively: Claude Code emits `system/api_retry` with `retry_delay_ms` and supports `--fallback-model sonnet,haiku` for overload; Codex emits `turn.failed`. The scheduler should treat provider 429s as a shared resource constraint across worlds — an argument for staggered launches and for the scheduler, not the agent, owning retry policy.

### (e) MCP as an inbound surface

Every Tier-1 surface consumes MCP servers (Claude Code `--mcp-config`/`--strict-mcp-config`; Codex `mcp_servers` in config.toml; opencode and OpenHands likewise), so **Multiverso can expose itself as an MCP server that agents query for their goal state**: `get_intent` (versioned intent + acceptance criteria), `get_policies` (oracle tiers, budget remaining), `report_evidence` (agent-submitted claims, typed V0-testimonial per ch. 14). Precedents for "agent queries its task via MCP" are established: the Linear MCP server exposes issue search/read/update so agents pull their assigned work mid-task ([overview](https://getunblocked.com/blog/linear-mcp/), [tacticlaunch/mcp-linear](https://github.com/tacticlaunch/mcp-linear)); [sammcj/mcp-github-issue](https://github.com/sammcj/mcp-github-issue) turns GitHub issues into agent tasks; the go-task runner has an open request to expose tasks over MCP ([go-task/task#2324](https://github.com/go-task/task/issues/2324)); and GitButler distributes agent-facing capability as installable skills plus CLI ([GitButler docs](https://github.com/gitbutlerapp/gitbutler-docs/blob/main/content/docs/ai-agents/getting-started.mdx)). Two cautions: (1) ch. 13's AI-control threat model says the generator is untrusted — the inbound MCP server must be world-scoped (a candidate can query only *its own* intent and budget, never sibling status or scheduler internals, which would enable gaming); (2) pass it with `--strict-mcp-config` (Claude Code) so the candidate's MCP surface is exactly what the control plane declared, and gate its use in `system/init`'s `mcp_servers` status before turn one.

## Recommendation for the PRD

1. **Define `AgentAdapter` as a subprocess-first contract with six operations**: `spawn(candidateSpec) -> RunHandle` (worktree path, pinned model + effort, budget triple {maxTurns?, maxUsd?, wallClockMs}, MCP config, env); `events(run) -> AsyncIterator<AdapterEvent>` normalized to `{run_started, message, tool_use, tool_result, retry, budget_tick, done}`; `interrupt(run, grace)` (SIGTERM, expect 143-class exit); `result(run) -> {exitClass, costUsd?, tokens, turns, sessionId, structuredOutput?}`; `diff(run) -> {baseOid, patch}` via `git add -A && git diff --binary` in the control-plane-owned worktree; `transcript(run) -> {casDigest, rawPath}`. Subprocess-first keeps the adapter language-neutral — Anthropic itself recommends CLI-subprocess for non-Python/TS hosts.
2. **Ship two Tier-1 adapters in the MVP Candidate Race**: Claude Code (`claude -p --bare --output-format stream-json --include-hook-events --max-turns N --max-budget-usd X --permission-mode dontAsk --strict-mcp-config --mcp-config multiverso.json`) and Codex (`codex exec --json --sandbox workspace-write -C <worktree> -m <model> --output-schema result.json`, `CODEX_API_KEY` scoped per invocation). This proves vendor-neutrality on day one with the two highest-volume agents.
3. **Budget enforcement is control-plane-primary, tool-native-secondary.** Only Claude Code enforces dollars natively; make the wall-clock timeout + event-fed token meter the authoritative kill mechanism, and treat `--max-budget-usd`/`--max-turns` as defense in depth. Emit a `budget_tick` event so the ch. 3 scheduler can reallocate mid-run.
4. **Bind the candidate to `(baseOid, patch, transcriptDigest, modelId, cliVersion)` in the receipt.** Never rely on replay determinism — no surface offers seeds, and Anthropic removed sampling parameters entirely on current models.
5. **Expose Multiverso as a world-scoped MCP server** (`get_intent`, `get_policies`, `report_evidence`) injected via `--strict-mcp-config`; deny sibling/scheduler visibility per the AI-control threat model.
6. **Defer** OpenHands (add as Tier-2 when a customer runs it; its SDK embedding and `Metrics` API are excellent but in-process Python), Aider (unsupported API), opencode (adapter is easy via `@opencode-ai/sdk` if demanded), and Jules (alpha API, cloud-only, no local diff — revisit at v1). **Adopt GitButler as neither**: it is a VCS-substrate option for ch. 4, and its own docs recommend worktrees for competing attempts — Multiverso's exact regime.

## Open questions

- **Cost figures are client-side estimates** (Claude Code) or token counts needing a price table (Codex). Is estimate-grade cost accounting acceptable inside admission receipts, or does the PRD need provider-billing reconciliation for FAR/TCAR budget-matched evaluation?
- **How stable is stream-json?** Claude Code gates behaviors by CLI version (`capabilities` array in `system/init`); the adapter needs a version-pinning and capability-detection policy per tool.
- **Shared rate-limit pools across N worlds**: should the scheduler model provider ITPM/OTPM as a first-class constrained resource (staggered launches, per-world token leases), and does that interact with budget-matched experimental arms (ch. 9)?
- **Inbound MCP and prompt-injection surface**: `report_evidence` accepts generator-authored claims; how are these typed (V0 testimonial) and rate-limited so a reward-hacking agent cannot flood the evidence ledger?
- **Codex cloud and Jules `--attempts`/multi-attempt modes** overlap with Multiverso's N-candidate generation. Are hosted attempt fan-outs a threat (incumbent assembles the loop) or an opportunity (adapter drives them as remote Worlds)?
